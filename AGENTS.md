- Dish categories: `dish_categories` is the per-restaurant list/order; `dishes.category` text stays the stored value (rename/merge via RPCs update it) — keeps Reports/POS/Captiva readers unchanged.
- Initial stock list import: parsing/matching is client-side (src/lib/stockListImport.ts) and writes nothing until Apply; starting prices go only through set_initial_import_price (source 'initial_import', refuses items with any price history) — keeps normal price-history behaviour untouched.
- Supplier products: `supplier_products` maps supplier descriptions/codes to one master ingredient; `supplier_product_prices` is append-only supplier evidence (corrections supersede, never edit) and never feeds recipe costing — keeps master costing on `ingredient_prices` only.
- Stock List import writes only through `apply_stock_list_import` (one transaction for suppliers, items, starting prices, supplier links/prices); conflicts are surfaced by `preview_supplier_products` and must be resolved row-by-row — prevents partial imports and silent remaps.
- Stock List photo/PDF input: `stock-list-extract` only reads (no DB writes, no storage) and its rows become a SheetGrid fed into the existing importer review and `apply_stock_list_import`; unclear cells must be resolved by the user — keeps one import path and never guesses values.
- Inventory item writes require `can_edit_inventory()` via RESTRICTIVE RLS policies on `ingredients` (insert/update/delete) and in `delete_or_archive_ingredient`; SECURITY DEFINER import/price functions keep their own checks — enforces Role Builder on the server, not just in the UI.
- Stock List import price decisions: changed supplier prices are recorded only via an explicit per-row `record_supplier_price`, and master recipe cost changes only via explicit `update_master_price` inside `apply_stock_list_import` (today = through the ingredient price-history trigger; backdated = one history row only when a newer master price already exists, otherwise refused, so a backdated entry can never become today's cost) — keeps supplier evidence separate from costing and prevents older lists replacing current prices.
- Physical stock changes only through the stock ledger functions (`record_stock_adjustment`, `submit_stock_count`, `receive_purchase_order`/`receive_direct_delivery`, `set_stock_quantity`, `reverse_stock_movement`); `stock_movements` is append-only and `stock_levels` always equals its sum (negatives allowed, never clamped); entries dated before a later count get an automatic `count_rebase` at the earliest later count — keeps counted balances and today's stock correct while late entries land in their own period.
- Supplier invoices, physical receipts and supplier payments are separate records: invoices never move stock (goods enter via receipt with a delivery date, one receipt per invoice), payments carry their own payment date and allocations — prevents duplicate receipts and keeps cash flow on payment dates.
- Actual food cost (`get_period_actual_food_cost`) and supplier cash flow are computed live from dated immutable records (no snapshots), separate food & beverage from non-food via `ingredient_cost_class`, and report Complete only when every reconciliation check passes — late entries recalculate history automatically.
